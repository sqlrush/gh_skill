### 相对上一版的变更摘要

**新功能**

- **慢 SQL / Top SQL 排除 GaussDB 自己的系统 SQL**：慢 SQL、Top SQL（累计 / 最近一段时间 / 某个时间段）、健康检查的慢 SQL 与时段 Top SQL、
  WDR 的 Top SQL 与各维度元凶，默认排除只访问系统表 / 系统视图 / 系统函数的语句（WDR 快照、监控采集、诊断工具自己的查询），
  报告里写明「已排除 N 条内核系统 SQL（合计 X 秒）」。拿不准的一律按业务 SQL 保留；正文被截断时按 sql_id 补取全文再判断。
  要连系统 SQL 一起看，慢 SQL 与 Top SQL 加 `--include-system`。取回来的全是系统 SQL 时，报告直说「没有业务语句」，不再提示去开统计。
- **知识库向量库改为 sqlite-vec**：向量与词法索引是知识库目录里的一个文件 `<kb>/index/store.sqlite`，`kb.py index` 建、各 skill 只读打开，
  **不再需要单独的高斯 / PG 向量库实例、库用户与口令**。图库 Neo4j 仍可选。
- **知识库入库前标准化（kb-init）能读照片**：手机直出的 HEIC 与扫描件 TIFF 自动转成 jpg 副本给模型看（不改原件）；
  同一份报告拍了多张照片时合并成一单。

**修复**

- kb-init 读照片时 read 报「this model does not support image input」：这是模型配置没声明图片输入，SKILL 里写明了原因与处理（第 5.3 节），
  不再让用户白跑一趟去转格式。

## 2. 安装 skill 包

```bash
# 依赖:新增 sqlite-vec(知识库向量检索)。离线环境按 CPU 架构取对应轮子,任何 Python 3 版本都能用同一个轮子
pip install sqlite-vec==0.1.9
# 离线:x86_64 用 sqlite_vec-0.1.9-py3-none-manylinux_2_17_x86_64.manylinux2014_x86_64.manylinux1_x86_64.whl
#       鲲鹏 aarch64 用 sqlite_vec-0.1.9-py3-none-manylinux_2_17_aarch64.manylinux2014_aarch64.whl

tar xzf gaussdb-skills-<提交号>-20261023.tar.gz
cd gaussdb-skills-<提交号>
bash install-opencode.sh --project /workspace      # skill 装到 /workspace/.opencode/skills，AGENTS.md 装到 /workspace/AGENTS.md
```

- 自检 sqlite-vec 能加载：`python3 -c "import sqlite3, sqlite_vec; c=sqlite3.connect(':memory:'); c.enable_load_extension(True); sqlite_vec.load(c); print(c.execute('select vec_version()').fetchone()[0])"`
  应打印 `v0.1.9`。报 `AttributeError: ... enable_load_extension` 说明这个 Python 编译时不许加载扩展（如 macOS 自带的 python）：
  知识库照常工作，只是没有向量召回；换一个 Python（如发行版自带或自编译的）即可。
- 安装脚本先把现有 skill 目录整体留成快照，出问题用 `bash install-opencode.sh --rollback` 回到上一版；原有的 `/workspace/AGENTS.md` 备份成 `AGENTS.md.bak.<时间>` 再覆盖。

## 5. 平台侧配置

### 5.1 知识库建新索引（用了知识库的必做）

```bash
python3 /workspace/.opencode/skills/gaussdb-kb/scripts/kb.py index     # 建 <kb>/index/store.sqlite
python3 /workspace/.opencode/skills/gaussdb-kb/scripts/kb.py health    # 状态行应为「模式:向量库+…」
```

建索引之前检索自动走文件模式（词法 + 图文件），不会中断；建好之后自动切换。`kb.yaml` 配了 embeddings 时会同时算向量。

### 5.2 下线原向量库（按需）

之前按 10 号手册装过知识库专用的高斯 / PG 向量库的：

- `kb.yaml` 里的 `store.pg` 段不再使用。留着不报错，`index` / `health` 会提示可以删掉；
- 凭据 `kb-pg` 不再需要（`python3 -m common.credential_cli` 可删）；
- 向量库实例本身可以下线——它只是派生索引，数据都在 `<kb>/` 的文件里，新索引由第 5.1 节重建。

### 5.3 读照片（按需）

1. **给模型声明支持图片输入**：opencode 只在模型配置里声明了图片输入时才把图片交给模型，否则 read 报
   「this model does not support image input」。在 opencode 配置里给所用模型加：

   ```json
   "models": { "<模型名>": { "name": "<模型名>", "modalities": { "input": ["text", "image"], "output": ["text"] } } }
   ```

   只在模型服务确实支持图片时加；纯文本模型加了，发图那一轮模型服务会报错。
2. **HEIC / TIFF 自动转换**：在跑知识库导入的那台主机上装 `pillow==12.3.0`、`pillow-heif==1.8.1`（两种架构都有现成轮子）。
   不装也能用，只是遇到 HEIC / TIFF 时会请用户自己转成 jpg / png 再传。

## 7. 安装后冒烟

在贵方沙箱里依次跑，`<句柄>` 是登录输出的那一串。

| # | 命令 | 期望 |
|---|---|---|
| 1 | `login.py --ip <实例> --database <库>` | 输出会话句柄；中间件应答正常 |
| 2 | `slowsql.py --session <句柄> --threshold 0 --limit 10` | 表格下方有「已排除 N 条内核系统 SQL」（实例上跑过诊断就会有）；`--include-system` 时这一行消失、系统 SQL 回到榜上 |
| 3 | `topsql.py --session <句柄> --window 1h` | 同上，增量表下方有排除说明 |
| 4 | `kb.py health`（用了知识库的） | 状态行「模式:向量库+…」，`向量:` 一项如实写 sqlite-vec 覆盖率或未启用原因 |
