# opencode 放进 k8s Pod：持久化拆分评估

日期：2026-09-15　依据：opencode 1.18.27（Mac 实机目录 + SQLite 表结构 + 官方文档）、gh_skill skills-v12.9 源码。

## 0. 结论

opencode 自己的持久化只有一处核心：**一个 SQLite 文件 `opencode.db`**（会话、消息、压缩摘要、待办、权限、分享记录全在里面），外加同目录下几个小目录。它没有独立的「记忆」组件，所谓记忆就是这个库里的历史和 AGENTS.md。所有目录位置都能用 `XDG_*` 环境变量改（实机验证过），**不需要改 opencode 源码**，靠环境变量和挂载就能把状态拆出去。

拆分后落到四类地方：

| 落点 | 放什么 | 生命周期 |
|---|---|---|
| **镜像** | opencode 二进制、skills、AGENTS.md、opencode.jsonc 模板、rg、models.json、Python 依赖 | 随版本发布 |
| **Secret / ConfigMap** | 模型 API key、GRMP 令牌、凭据加密钥匙、连接配置 | 平台管理，按人或按环境注入 |
| **按人 PVC（RWO）** | `opencode.db` 及同目录、`/workspace`、skill 会话目录、上传文件 | 跟人走，Pod 销毁不删 |
| **共享组件** | 知识库（Md Pod）、向量库、图谱库、日志系统 | 独立于 Agent Pod |

其余全部可丢弃（emptyDir）。

## 1. opencode 原生持久化清单

目录默认在 `~/.local/share`、`~/.config`、`~/.local/state`、`~/.cache` 下的 `opencode/`，分别由 `XDG_DATA_HOME`、`XDG_CONFIG_HOME`、`XDG_STATE_HOME`、`XDG_CACHE_HOME` 控制。在 Mac 上用四个变量指到临时目录跑了一次，四个目录全部按新位置创建。

### 1.1 数据目录 `$XDG_DATA_HOME/opencode/`　→ 按人 PVC

| 文件 / 目录 | 内容 | 实机大小 | 处置 |
|---|---|---|---|
| `opencode.db` + `-wal` + `-shm` | SQLite。表：`project`、`project_directory`、`workspace`、`session`、`message`、`part`、`todo`、`permission`、`session_share`、`event`、`credential`、`account`、迁移表 | 38 MB（137 会话、1455 条消息、5129 个片段） | **必须持久化，按人**。三个文件一起搬 |
| `tool-output/` | 大体积工具输出落盘，消息里只留引用 | 0 | 跟 db 一起 |
| `snapshot/<项目>/` | 工作目录的 git 快照，用于「撤销到某一步」 | 2.7 MB | 跟 db 一起；丢了只是不能撤销 |
| `repos/` | 远端仓库克隆缓存 | 0 | 可丢弃 |
| `log/` | 运行日志 | 14 MB | 可丢弃，采集到日志系统 |
| `auth.json` | `opencode auth login` 写入的 provider 凭据 | — | **不应产生**，见 3.3 |
| `storage/` | 老版本文件存储的残留（`migration`、`session_diff`） | 24 KB | 可丢弃 |

`session` 表里和部署直接相关的列：`project_id`、`directory`、`workspace_id`、`share_url`、`summary_*`、`time_compacting`、`revert`。**会话绑定的是目录路径**（`directory` 列，`project_directory` 表做路径 → 项目映射）。

### 1.2 配置目录 `$XDG_CONFIG_HOME/opencode/`　→ 镜像

`opencode.jsonc`、`AGENTS.md`、`skills/`、`agents/`、`commands/`、`plugins/`。全部是版本化内容，随镜像发布，只读挂载即可。`OPENCODE_CONFIG_DIR` 也能指定这个目录。

### 1.3 状态目录 `$XDG_STATE_HOME/opencode/`　→ 按人 PVC（可选）

`model.json`（上次选的模型）、`prompt-history.jsonl`（输入历史）、`kv.json`、`locks/`。共 12 KB。放按人 PVC 体验好一点，放 emptyDir 也没有损失；`locks/` 必须是本地目录。

### 1.4 缓存目录 `$XDG_CACHE_HOME/opencode/`　→ 镜像

`models.json`（models.dev 的模型清单缓存，8 MB）、`bin/rg`（自动下载的 ripgrep）。内网拉不到，**预先烧进镜像**，否则首次启动会去外网。

### 1.5 工作目录（现场是 `/workspace`）　→ 按人 PVC

不是 opencode 的目录，但和它强绑定：

- 会话按这个路径归属项目，路径变了老会话不在列表里。
- 用户上传的文档、模型保存的报告（如 `wdr --out`）都落在这里。
- 项目级 `AGENTS.md`、`.opencode/` 也在这里读（配置的一部分，可从镜像复制进来）。

## 2. 「记忆」在哪里

opencode 没有单独的长期记忆机制。四样东西合起来是它的记忆：

| | 位置 | 性质 |
|---|---|---|
| AGENTS.md | 配置目录 + 工作目录 | 静态规则，随镜像 |
| 会话历史 | `message` / `part` 表 | 每轮重发给模型 |
| 压缩摘要 | 同上，作为一条消息保存（`session.time_compacting` 记时间） | 上下文超限后代替早期历史 |
| 待办 | `todo` 表，按会话 | 任务内 |

所以「记忆持久化」= 持久化 `opencode.db`，没有第二个地方。

## 3. 不该放进持久卷的东西

### 3.1 分享功能

`session_share` 表说明 opencode 会把会话分享到 opencode.ai。配置里 `share` 默认是 `manual`（允许手动分享）。**必须设成 `"disabled"`**，写进镜像里的 `opencode.jsonc`。

### 3.2 日志

`log/` 每天增长，放集中日志系统，不进 PVC。

### 3.3 provider 凭据

`opencode.jsonc` 支持 `{env:VAR}` 和 `{file:path}` 占位。模型 API key 从 Secret 注入环境变量，配置里写 `{env:MODEL_API_KEY}`，这样不会产生 `auth.json`，`credential` / `account` 表也保持为空。**不要让用户在 Pod 里跑 `opencode auth login`**。

## 4. gh_skill 这一侧的持久化

| 路径 | 内容 | 处置 |
|---|---|---|
| `$GSDB_HOME/config.yaml` | 连接定义、api 模式配置 | ConfigMap，按环境 |
| `$GSDB_HOME/key` | 凭据加密钥匙 | Secret |
| `$GSDB_HOME/credentials/*.enc` | 直连模式的库口令 | Secret；**api 模式不需要** |
| `$GSDB_HOME/grmp.env` | GRMP 令牌 | Secret，按人注入 |
| `$GSDB_HOME/sessions/<句柄>.yaml` | 登录会话（实例、库、句柄；12 小时过期） | 见 5.3 |
| `$GSDB_KB_DIR/` | 知识库文件 | 共享（Md Pod / 只读卷） |
| `$GSDB_KB_INBOX/` | 用户上传待导入的文档 | 按人 PVC |
| `<kb>/index/misses.log`、向量缓存 | 检索过程产物 | 可丢弃，写不进去也不报错 |
| `<kb>/eval/feedback.yaml` | 用户反馈 | 需要写共享库，只读卷上会报错；阶段一放管理员 Pod，阶段二走 kb-api |
| 报告文件 | 模型按 `--out` 写到工作目录 | 跟 `/workspace` 走 |

**一个必须改的点**：`GSDB_HOME` 没设时，默认值是 `/workspace/.opencode/skills/common`，也就是 skills 安装目录里面。skills 一旦放进镜像只读，会话文件就写不进去。Pod 里必须显式设 `GSDB_HOME` 指向 PVC 上的目录。

## 5. 落地时的注意事项

### 5.1 SQLite 不能放共享存储

`opencode.db` 是 WAL 模式，靠文件锁；放 NFS / CephFS 这类 RWX 卷有损坏风险。每人一个 **RWO 块存储卷**（Ceph RBD、云盘），一个 Pod 独占。这和「每人一个 Pod」正好吻合。

### 5.2 优雅停机

Pod 销毁前要让 opencode 把 WAL 合并回主库：`terminationGracePeriodSeconds` 给 30 秒以上，preStop 先停网关流量再发 SIGTERM。强杀不会丢已提交的数据，但会留下 `-wal` 文件，下次启动自动恢复。

### 5.3 skill 会话文件放哪

会话文件里记录了中间件地址（09-14 的问题根源）。两个选择：

- **现在**：放 emptyDir。Pod 重建即失效，用户重新登录一次。12 小时过期本来就短，代价小；而且 Pod 重建时配置更新，不会带着旧地址。
- **改完 skill 不再存地址之后**：可以放按人 PVC，Pod 重建不用重登。

推荐先用 emptyDir。

### 5.4 路径固定

`/workspace`、`$XDG_DATA_HOME` 的挂载路径在 Pod 重建前后必须一致，否则会话归属的项目对不上。

### 5.5 版本升级

`opencode.db` 有迁移表（`__drizzle_migrations`），换新镜像启动时自动迁移，**迁移不可回退**。升级前对按人 PVC 做快照。

### 5.6 容量与回收

- 实机 137 个会话 38 MB，加快照、上传文件，每人 2 GB 足够。
- PVC 按工号命名，Pod 销毁不删；离职由平台回收。
- 备份：PVC 快照；知识库走 Git，不在此列。

## 6. 需要动手的清单

| 谁 | 事项 |
|---|---|
| 镜像 | 烧入 opencode、skills、AGENTS.md、`opencode.jsonc`（`share: "disabled"`、API key 用 `{env:}`）、`rg`、`models.json`、Python 依赖 |
| 平台 | 四个 `XDG_*` 指到 PVC / emptyDir；`GSDB_HOME`、`GSDB_KB_DIR`、`GSDB_KB_INBOX` 显式设置；Secret 注入令牌和钥匙；RWO PVC 按工号；preStop；路径固定 |
| skill（可选） | 会话文件不再存中间件地址，之后会话目录才能进 PVC |
| opencode | 不用改源码 |
