# 交付手册：skills-v12.23（2026-11-03）

本手册覆盖从 `skills-v12.22` 到本次的全部动作。容器版同一批改动的版本号是 `agent-v1.4.4`。
本次一项改动：知识库里处置方案的「取代」——同一根因下的处置变了，由模型判断、管理员确认，旧做法标失效、历史保留。

| 1 | 装新包（`--project /workspace`，与上一次相同） | 平台 | 第 2 节 |

**不用做**：白名单（不变，仍是 128 条）、`AGENTS.md`、环境变量、已有的知识库文件（不用改、不用重建索引）。

## 1. 本次交付物与变更

| 项 | 说明 |
|---|---|
| skill 包 | `gaussdb-skills-<提交号>-20261103.tar.gz`，对应标签 `skills-v12.23` |
| 白名单 | 不变（128 条） |

版本号：gaussdb-kb 3.4.0，其余不变。

- **处置的「取代」**：同一根因下的处置方案变了（参数值调整、手工改为定时自动等），导入新案例时模型对同根因的旧处置逐条判断是
  「取代」还是「并存」（附理由与原文摘录），审核清单里列出，**取代由管理员确认才生效**（没有默认值）。被取代的旧做法在关系图上标
  失效日期与取代它的案例，**旧案例文件不改、历史保留**；谁取代谁按案例发生日期（补导旧工单时被取代的是它自己）。
- **检索**：现行做法排在前面，处置全被取代的案例排后并标「已被 X 取代」；处置路径的「N 个案例支持」按处置算，
  不再把不同处置的案例混在一起数。专题页同样标注。
- **归一提示**：现象 / 根因换了说法（字面相近）时，审核清单与 `validate` 提示归一；实体归一只比同类（以前参数名会被建议并进处置节点）。
  意思相同而字面差得远的说法（如「高CPU」与「CPU使用率高」）字面算法抓不到，由模型对照已有名称处理。
- **validate**：取代关系指向不存在的案例、只标了取代没标失效日期，报错。

## 2. 安装 skill 包

```bash
tar xzf gaussdb-skills-<提交号>-20261103.tar.gz
cd gaussdb-skills-<提交号>
bash install-opencode.sh --project /workspace
```

已有知识库照常可用：没有取代关系时检索结果与以前相同；以后导入新案例时才会出现取代判断。

## 3. 回滚

`bash install-opencode.sh --rollback`。已经确认过的取代关系写在知识库的关系图文件里（边上的 `valid_to` / `superseded_by`），
旧版 skill 本来就认 `valid_to`（失效的处置不进处置路径），只是不再标「已被 X 取代」、也不把这些案例排后。
