### 相对上一版的变更摘要

- **会话按句柄分文件**（v11）：同一沙箱多人登录不再串库；api 模式下每条命令带 `--session <句柄>`。
- **表名不带 schema 的业务 SQL**（v12～v12.7）：按 sql_id 时自动取 statement_history 记录的 schema；能切 search_path 就切，执行器跑不了两条语句时脚本自己把表名补全成 `schema.表` 后取计划；贴文本没带 `--schema` 时按表名在目录里推断，同名表跨 schema 列出候选不猜；explain 新增 `--sql-id`。
- **包内存储过程**（v12.1）：`schema.package.proc` 三段名；同名过程不猜。
- **过程找不到时代为排查**（v12.5）：自动区分连错库、执行账号无权限（对象隔离藏 schema）、本身不存在，给编号问题清单与 DBA 核对 SQL。
- **知识库导入**（v12.5）：用户给本机路径时指明沙箱收件目录；`kb.py health` 显示收件目录。
- **gs_get_explain / gs_get_kernel_info**（v10～v10.4）：有则用运行态计划与内核水位，无则退回；签名按 505.2.1 实测的 `bigint`。
- **报错中文化**：备机、权限不足、函数不存在三类报错给出核对步骤。

## 4. AGENTS.md 操作

### 4.1 opencode 怎么用它

opencode 把两处文件当作全局规则读进每次对话：**项目根目录的 `AGENTS.md`**（项目根就是 opencode 启动时的工作目录，贵方沙箱里是 `/workspace`）和全局的 `~/.config/opencode/AGENTS.md`；`opencode.json` 的 `instructions` 还可以追加别的文件，几份内容合并生效。截图里模型说「根据 AGENTS.md 的要求」，读的就是 `/workspace/AGENTS.md`。

两点要知道：

- 文件开头那段 YAML（`mode`、`permission` 等）是 opencode **agent 定义文件**的格式，只在 `.opencode/agents/<名字>.md` 或 `~/.config/opencode/agents/` 下、并且选中该 agent 时才生效。放在 `AGENTS.md` 里它只是一段文字，不会真的限制工具。要让权限白名单真正生效，把 `permission` 那一段放进 `opencode.json`（`"permission": {…}`），或者建成 agent 文件并在调用时选中它。截图里模型标着 `Build`，说明当前用的是默认 agent。
- `AGENTS.md` 与各 skill 的 `SKILL.md` 都会被模型读到；两边说法不一致时模型会先按 `AGENTS.md` 排步骤。所以本次改的三条规则必须落在 `AGENTS.md` 里，只改 SKILL.md 不够。

## 5. 平台侧配置

| 项 | 做什么 | 不做的后果 |
|---|---|---|
| 知识库上传入口 | 对话界面加「上传文件」，文件原样写到该用户沙箱的固定目录；目录不是默认的 `<kb>/inbox/uploads` 时，给沙箱设环境变量 `GSDB_KB_INBOX=<目录>` | 用户只能把文本贴进对话由模型写文件，docx/pdf 无法导入 |
| 会话句柄（可选） | 宿主按用户往沙箱注入环境变量 `GSDB_SESSION=<句柄>` | 靠模型在命令里带句柄；句柄传错脚本识别不了 |
| dataIp 指向主库 | 中间件调度到主库实例 | 备机上 `statement_history` 读不到，按 sql_id 只能拿归一化文本，explain 会拒绝并指到 sqltune |

## 6. DBA 侧配置

1. **给中间件执行账号设 search_path（根治）**。skill 里的切换、补全、推断都是兜底，这条做了以后表名不带 schema 的 SQL 在任何路径上都能解析：

   ```sql
   ALTER ROLE <中间件执行账号> IN DATABASE <业务库> SET search_path = <业务 schema>, public;
   ```

   新连接生效，不用重启。
2. **确认业务账号的 search_path 有几个 schema**：`SELECT rolconfig FROM pg_roles WHERE rolname = '<应用账号>';`。多于一个 schema 时，只有上面这条按同样的顺序设全才能覆盖跨 schema 的 SQL，skill 会列出候选停下来问。
3. **开了对象隔离（`ENABLE PRIVATE OBJECT`）的库**：给执行账号相关 schema 的 `USAGE`（包还要 `EXECUTE`），否则 procinfo 会停在「schema 对执行账号不可见」那一档，把 GRANT 命令交给 DBA。

## 7. 安装后冒烟

在贵方沙箱里依次跑，`<句柄>` 是登录输出的那一串。

| # | 命令 | 期望 |
|---|---|---|
| 1 | `login.py --ip <实例> --database <库>` 后 `login.py --status` | 列出会话与句柄；中间件应答正常 |
| 2 | `sqltune.py --session <句柄> <一条业务 sql_id>` | 报告头部有 `Schema:` 与 `Search path:` 行，出执行计划；不再 400 |
| 3 | `explain.py --session <句柄> --sql-id <同一 sql_id>` | 「来源:」行带 `sql_id=…;schema=…`，出计划 |
| 4 | `procinfo.py --session <句柄> <schema>.<包>.<过程>` | 出源码；或出「过程未找到」排查报告与编号问题清单，不是一句错 |
| 5 | `kb.py health` | 有「收件目录」一行 |

冒烟里任何一条报 `未注册脚本 xxx` 或 `HTTP 400 … 脚本不存在`，回到第 3 节核对该脚本是否灌入。
