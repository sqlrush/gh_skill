版本号：procinfo 2.3.0、proctune 2.5.0，其余不变。

- **pg_proc 取不到源码时改查 ADM_SOURCE**：开了对象隔离（`ENABLE PRIVATE OBJECT`）的库，普通账号查 pg_proc 受行级访问控制，
  联表 0 行，以前只能给出「过程未找到」的排查报告。现在接着按 ADM_SOURCE 取源码：独立过程直接分析；包内过程从包体里切出来，
  报告里写明取自包体第几行，并附上包级声明（包级变量、常量、游标）。pg_proc 能取到时，行为与输出都不变。
- **取不到时说清原因**：ADM_SOURCE 也取不到时，「过程未找到」报告多一行写明原因——中间件还没登记脚本、本库没有该视图、
  或执行账号没有读权限；没有读权限时，问题清单与 DBA 处理里给出授权语句（第 4 节），授不授由贵方决定。
- **不猜**：同名重载（ADM_SOURCE 不带形参，分不出是哪一个）、同名对象有多个所有者又对不上给出的 schema、源码超过 2 万行时，
  拒绝分析并说明原因。包内过程请写全 `schema.包名.过程名`（或 `包名.过程名`）。

## 4. 授 ADM_SOURCE 的读权限（按需，由贵方 DBA 决定）

ADM_SOURCE 默认只有系统管理员能读。执行账号不是系统管理员、库又开了对象隔离时，要授权才能取到源码：

```sql
GRANT SELECT ON pg_catalog.adm_source TO <中间件执行账号>;
```

ADM_SOURCE 能看到全库所有存储过程、函数、触发器、包的定义，授不授由贵方决定。不授权时，「过程未找到」报告里照旧给出
schema USAGE / 包 EXECUTE 的授权方案。

**首次上线请 DBA 用中间件执行账号执行下面三条，把结果发给我方**——我方没有 GaussDB 505 环境，视图的实际形态
（`owner` 是用户名还是模式名、`text` 是否带过程头与行尾换行）以贵方结果为准，技能对几种形态都做了兼容：

```sql
SELECT owner, name, type, count(*) FROM pg_catalog.adm_source WHERE lower(name) = lower('<一个包名或过程名>') GROUP BY 1, 2, 3;
SELECT line, text FROM pg_catalog.adm_source WHERE lower(name) = lower('<同上>') ORDER BY line LIMIT 5;
SELECT pg_get_viewdef('pg_catalog.adm_source');
```
