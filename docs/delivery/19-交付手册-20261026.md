### 相对上一版的变更摘要

**新功能**

- **回答模板化**：健康检查、故障排查、SQL 优化、知识问答、WDR 解读、Top SQL / 慢 SQL 榜单各有固定版式，共用开头（总体状态 → 短结论）
  与结尾（「需要就 xxx 展开说明吗？」）；正文每段先「应用视角」（给开发人员）、再「数据库机制」（给数据库工程师）。
  SQL 优化增加现状与趋势（执行次数、平均 / 最大耗时、近 7 天按小时的变化、哪个时间点突然变慢、当时执行计划变没变）与改写前后对比。
  WDR 报告重排为：负载画像 → 问题与元凶 → 解决方案 → 总结和结论 → 附录。详见 18 号说明。
- **知识引用上色并注明出处**：出自知识库的句子写进正文并上色，句后括号注明出处，例如「……（引用自贵行规范库 GS-CHG-003）」。
  贵方自己的规范、案例、手册、基线等蓝色 `#2f6fdb`；产品文档（官方文档集与贵方导入的产品文档）青色 `#0f7c86`。
- **知识类型（八类）**：规范、案例、环境画像、指标基线、已知缺陷、处置手册、产品文档、Wiki。类型 = 目录，每类按自己的要点校验；
  导入时模型提议类型、人确认、脚本校验落盘（`kb.py template / add / attach / retype / migrate / profile / taxonomy`）。
  案例增加排查思路（候选原因、取证顺序、排除理由、最终验证）与区分证据。
- **渐进式披露（L0–L3）**：`kb.py index` 生成 L0 总索引与每个专题的 L1 导航；模型按层取（`overview / topic / show / evidence`），
  引用步骤、审批、版本结论之前必须读全文。
- **适用性判断**：条目与本实例画像的产品系列、版本、系统不符时标「不适用本环境」并降权；已知缺陷写「本环境版本受影响 / 不受影响」。
- **官方文档集**：GaussDB 官方文档（CHM）按目录切分成标准知识库的一层（条目 ID `PD-<代号>-NNNNN`），可整体退役、换版。
- **更多诊断 skill 单独运行时也检索知识库**：等待事件、vacuum、WDR、内存、存储过程、SQL 审核。
- **中间件接口路径前缀改为部署配置**：两个诊断接口 `<前缀>/common-operations`、`<前缀>/common-operations/invoke` 的前缀由环境变量
  `GRMP_PATH_PREFIX` 提供，代码里不再写死；没配时登录直接报「GRMP_PATH_PREFIX 没配」，不拿猜的前缀去请求中间件。
- **容器版凭据代理**：技能在容器里经同 Pod 的凭据代理调中间件，令牌与 SM2 私钥不再放进模型所在的容器
  （环境变量 `GRMP_PROXY_SOCKET` 指向代理时自动走代理；非容器安装不受影响，照旧直连）。

**修复**（用演练库造出 34 类典型故障、两轮全量验证后发现）

- 健康检查 / vacuum：长事务与空闲事务漏报（客户端会话的认法）、统计过期漏报从没分析过的表、连接数把线程池空闲条目算进去；新增「执行中的长 SQL」。
- 锁等待：最近几小时的锁等待一律「回看不了」（只读了落表样本）；锁类型说明张冠李戴。
- 内存分析：负值、参数误报「没开」。WDR：等待缺事件名。
- SQL 调优：按 sql_id 调优因占位符失败、根因提示缺失。Top SQL：分出等待耗时与自身耗时。
- 知识库：短问题与领域词查不到案例；没有工单号的标准化工单导入时互相覆盖；`template` 列出必填项、建议项与可选取值。

## 5. 平台侧配置

### 5.0 中间件接口路径前缀（必做）

```bash
export GRMP_PATH_PREFIX='<中间件接口路径前缀>'     # 以 / 开头、只写路径、末尾不带 /,形如 /xxx/grmp/diagnostic/agent
```

放进运行 opencode 的环境（与 `GRMP_API_HOST`、`GRMP_AUTH_TOKEN` 同一处）；容器版填在 `agent-config` 的 `GRMP_PATH_PREFIX`。
值与上一版内置的前缀相同，向中间件团队确认。没设时 `login.py` 直接报「中间件接口路径前缀没有配置:环境变量 GRMP_PATH_PREFIX」。

### 5.1 知识库迁移与重建索引（用了知识库的必做）

```bash
KB=/workspace/.opencode/skills/gaussdb-kb/scripts/kb.py
python3 $KB migrate             # 出迁移清单:旧指南提议归到手册 / 产品文档 / Wiki,条款与案例补专题
#   → 清单原样给知识库管理员确认,按回答改清单
python3 $KB migrate --apply
python3 $KB validate && python3 $KB index     # index 生成 L0 总索引与 L1 专题导航
python3 $KB health
```

**不迁移也能用**：没类型的条目显示「未分类」，检索照旧；只是拿不到类型化的校验与按层导航。产品文档必须补产品系列与版本才迁得过去。

### 5.2 登记环境画像（按需）

```bash
python3 $KB profile --system <系统代号> --alias <连接别名> --version-string "<登录输出里的版本串>"
#   → 补全起草出的画像后 kb.py add
```

诊断时按连接别名匹配本实例画像，判断条目适不适用；**画像只写连接别名，不写 IP、主机名与口令**。没有画像时一律写「适用性未知」。

### 5.3 导入官方文档集（按需）

在知识库导入环境里让模型按 gaussdb-kb 的「官方文档集」流程走（扫描 → 用户确认四项 → 配方 → 落盘 → 校验 → 建索引）：

```bash
python3 $KB docset scan <官方文档.chm>
python3 $KB docset plan <批次> --code <代号> --product "<产品系列>" --versions <版本> --deployment "<部署>"
python3 $KB docset apply <批次> && python3 $KB docset validate <代号> && python3 $KB index
```

换下一版文档时另起代号导入，旧的 `kb.py docset retire <代号>` 整体退役。官方文档原件只进贵方的知识库，不进任何代码仓库。

### 5.4 自有对话前端（按需）

回答里出自知识库的句子用 `<font color=#2f6fdb>…</font>`（贵方自己的知识）与 `<font color=#0f7c86>…</font>`（产品文档）上色。
自己渲染回答的前端要保留这两种颜色（HTML 白名单放行 `font` 的 `color` 属性）。

## 6. DBA 侧配置（按需）

SQL 优化的「近 7 天趋势」能看多远，取决于 WDR 快照保留期 `wdr_snapshot_retention_days` 与语句历史的保留期；
保留期短于 7 天时，回答里如实写「只能看到最近 N 天」。不改参数也能用。

## 7. 安装后冒烟

在贵方沙箱里依次跑，`<句柄>` 是登录输出的那一串。

| # | 命令 / 问法 | 期望 |
|---|---|---|
| 1 | `login.py --ip <实例> --database <库>` | 输出会话句柄；中间件应答正常 |

## 8. 回滚

- skill：`bash install-opencode.sh --rollback` 回到上一版快照（上一版不读 `GRMP_PATH_PREFIX`，留着无妨）。
- 白名单：一般不用回退——新增的 3 条旧 skill 不调用，更新的 12 条只修取数口径、输出列只增不减。唯一例外是 `health.stale_stats`：
