# 版本与回滚

装到 OpenCode 上的 skill 表现不好时，怎么退回上一版。

## 版本标签

| 标签 | 内容 |
|---|---|
| `skills-v1` | 代价推演之前的基线。中间件走通、全部 skill 迁到统一取数入口、交付 DML 74 条。sqltune 的索引建议只有「未验证」三个字 |
| `skills-v2` | 代价推演 + health 证据化。sqltune 出逐项可复核的算式；health 三条发现摆判定依据与观测窗口；交付 DML 77 条 |
| `skills-v3` | 新增 `gaussdb-login`，配置改成 `connection_mode` + 应用分组格式。13 个 skill 不带 `-c` 时用登录建立的会话 |
| `skills-v4` | **配置文件禁止明文口令**；api 模式改收「实例 IP + 库名」两项；新增交互式 `deploy.sh` |

### v4 有两处破坏性变更

**一、配置里的明文口令会让加载直接失败。**

v3 及更早允许 `password: 明文`（或 `encrypted: false`）。v4 起一律拒绝。
升级前先把口令挪进凭据目录：

```bash
python3 -m common.credential_cli set <连接名>     # 交互输入，不回显
```

然后删掉 config.yaml 里该连接的 `password` / `encrypted` 两行。

不这么做的表现是：**所有 skill 都报「password 是明文」并停下**——不是静默降级，
所以不会有人在不知情的情况下继续用明文跑。

**二、api 模式必须同时给 `--ip` 和 `--database`。**

v3 只要 `--database`（它同时充当 dataIp）。v4 起两项都要：IP 进 dataIp 供中间件
定位实例，库名决定取数落在哪个库并写进报告抬头。

只给一项时会停下来提示缺哪个，不会猜。

> 回滚到 v3 时这两条都自动恢复（v3 的代码接受明文、也接受单 `--database`），
> 但**配置文件不会自动改回去** —— 挪进凭据目录的口令留在那儿照样能用，
> 所以这个方向没有额外动作。

### v3 的一个额外注意

v3 **换了配置格式**。回滚到 v2/v1 时代码只认得 `connections:` 平铺列表，
而 v3 已经把 `~/.gdaa/config.yaml` 改成了 `db_connections:` 分组格式 ——
**回滚代码不会自动回滚配置**，此时所有 skill 会报「没有名为 xxx 的连接」。

回滚前先把配置也换回去：

```bash
ls -t ~/.gdaa/config.yaml.bak.*        # v3 升级时自动备份过
cp ~/.gdaa/config.yaml.bak.<时间戳> ~/.gdaa/config.yaml
```

反过来（v1/v2 → v3）不用管：新代码两种格式都认。

看当前装的是哪一版：

```bash
cd ~/gh_skill/opencode_skill-main-v2-0729
git describe --tags
```

## 回滚：两条路

### 路一：还原安装快照（最快，不碰仓库）

每次装之前都会把当前安装目录整份备份：

```bash
ls -dt ~/.config/opencode/skills.bak.* | head -5
```

挑一个还原：

```bash
BAK=~/.config/opencode/skills.bak.20260806-001306   # 换成要回的那个
rm -rf ~/.config/opencode/skills
cp -R "$BAK" ~/.config/opencode/skills
```

**这条路只还原 OpenCode 里跑的那份，仓库不动。** 适合「先把线上退回去，回头再查」。

### 路二：从仓库重装某个版本

```bash
cd ~/gh_skill/opencode_skill-main-v2-0729
git stash            # 有未提交改动的话
git checkout skills-v1
bash install-opencode.sh
```

回到最新：

```bash
git checkout main && bash install-opencode.sh
```

## 装之前先备份，不要省这一步

```bash
cp -R ~/.config/opencode/skills \
      ~/.config/opencode/skills.bak.$(date +%Y%m%d-%H%M%S)
```

安装脚本**不会**自己备份 —— 它对目标目录是 `rm -rf` 后重拷。

## 一个曾经踩过的坑

`install-opencode.sh` 早先**只装 skill 代码和 common/，不装 `scripts/registry/`**。
于是 skill 代码更新了、它调用的白名单脚本还是旧的，两边各自漂移。

实际后果：安装目录里 89 条脚本、仓库里 90 条，sqltune 直接 `KeyError: 'curpages'`
—— 因为部署的 `tables.yaml` 还没有那一列。

**那次是响亮地报错，所以当场发现了。** 但如果漂移的是某条 SQL 的正文而不是列名，
skill 会安静地跑旧查询，输出看起来完全正常。已修：安装脚本现在一并安装 registry。

回滚时同理 —— 用上面两条路的任意一条，代码和 registry 会一起回到同一版本，
不要只手工拷 skill 目录。

## 回滚之后

如果是因为某个 skill 表现不好而回滚，记一下**是哪个 skill、什么输入、期望什么、
实际给了什么**。skills-v2 的所有结论都带证据段（推演算式、判定依据、观测窗口），
把那一段贴出来最省事 —— 能直接看出是数据取错了、判据不对、还是措辞的问题。
