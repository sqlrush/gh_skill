# 客户知识库安装手册:gaussdb-kb + SQLite 索引(sqlite-vec)+ Neo4j 图库(可选)

> 面向部署/运维:从一台只装了 OpenCode 的主机开始,把 `gaussdb-kb` 装到能跑 `kb.py health` 显示「模式:向量库+…」。
> 本文把散在 `01-installation.md`(skill 安装)、`skills/gaussdb-kb/references/storage-setup.md`(接入配置)、
> `09-客户知识库.md`(原理与使用)和 `scripts/kb/containers.sh`(测试容器)里的内容收拢成一份,并补上 Neo4j 本身的安装。
> 原理、案例格式、检索策略不在这里重复,见 `09-客户知识库.md`。
>
> **2026-10-23 起向量库改为知识库目录里的一个文件 `<kb>/index/store.sqlite`(SQLite + sqlite-vec),原高斯 DataVec / PG pgvector 向量库下线**:
> 不再需要知识库专用的数据库实例、库用户、口令与端口。从旧版本升级见 9.4。

## 0. 先看一眼:装什么、装在哪、谁连谁

```
 OpenCode 主机                                   知识库专用 Neo4j(可选;可同机,可分机)
 ┌────────────────────────────────────┐          ┌──────────────────────────────┐
 │ ~/.config/opencode/skills/         │  HTTP    │ Neo4j 5 社区版(只存图)       │
 │   common/ (含 common/kb/)          │ ───────▶ │   /db/neo4j/query/v2         │
 │   gaussdb-kb/  gaussdb-*/          │ 7474     └──────────────────────────────┘
 │ ~/.config/opencode/kb/   = <kb>    │
 │   kb.yaml + rules/ cases/ graph/ … │
 │   index/store.sqlite               │ ← 向量 + 词法索引(SQLite + sqlite-vec)
 │ $GSDB_HOME/credentials/            │   kb.py index 写,各 skill 只读打开
 │   kb-graph.enc(配了 Neo4j 才要)    │
 └────────────────────────────────────┘
          │ HTTP(可选)
          ▼
   embedding 端点(OpenCode provider 或 Ollama 等,/v1/embeddings)
```

七条铁律,装之前先认下来:

1. **向量库不用装。** 向量 + 词法索引是 `<kb>/index/store.sqlite` 一个文件,`kb.py index` 建它、更新它,不用任何配置;
   没有数据库实例、库用户、口令、端口要准备。
2. **文件是唯一真相。** `<kb>/` 目录下的 rules / cases / graph 才是知识库;`index/store.sqlite` 与 Neo4j 都是
   `kb.py index --rebuild` 可重建的派生索引。备份只备 `<kb>/`,索引坏了重建。
3. **索引只有一个写方。** 只有 `kb.py index` 写索引:持知识库写锁、在同目录的临时副本上写、写完原子替换;
   读方(各诊断 skill)以只读方式打开(`mode=ro&immutable=1`),任何时刻看到的都是完整的一份——`<kb>/` 只读挂载给诊断侧也能用。
4. **Neo4j(若装)用专用实例,不放业务数据。** `kb.py index` 每次整体重建图;`kb.py` 经 HTTP(urllib)直连 Neo4j,**不经 GRMP**,
   OpenCode 主机到 Neo4j 7474 的网络必须打通。知识库不连被管业务库。
5. **口令只进加密凭据**(`$GSDB_HOME/credentials/*.enc`;现在只有 Neo4j 的 `kb-graph`),`kb.yaml` 出现 `password / apikey / token` 直接报错。
6. **向量是可选的。** 没有 embedding 端点、或 sqlite-vec 加载不了(没装,或 Python 不许加载扩展,如 macOS 系统自带的 python),
   知识库照样工作(词法 + 图),状态行会如实写「向量:未启用(原因)」。
7. **模式由脚本每次运行时探测,不需要任何开关。** 导入流程与报告小节格式在三种模式下完全相同:

| 状态行 | 什么时候 | 检索 |
|---|---|---|
| `模式:向量库+图库` | 索引在,Neo4j 配了且连得上 | 词法 ∥ 向量 ∥ 图三路 |
| `模式:向量库+图文件` | 索引在,Neo4j 没配或连不上 | 词法 ∥ 向量;路径从 `graph/*.yaml` 已确认边走 |
| `模式:文件(原因)` | 还没 index,或索引文件打不开 | 直接在 `<kb>/` 文件上做词法 + 图文件;少的只有向量语义召回 |

`<kb>/index/` 里的东西(都是派生的):

| 文件 | 内容 |
|---|---|
| `store.sqlite` | 文档头、切块正文、词法倒排(term → 块、词频)、块向量与图节点向量、`kb_meta`(vector_engine / dims / schema_version) |
| `store.sqlite.tmp-<pid>` | `index` 写时的临时副本,写完换上去;没有 `index` 在跑时留下的可以删 |
| `embed-cache/` | embedding 结果按内容哈希缓存,重跑不重算 |
| `state.json`、`misses.log` | 上次 index 的统计;查不到的发现(`health` 汇总成缺口清单) |

- 词法:BM25 由我们的代码在 SQLite 表里的倒排上算,与文件模式同一套算式、同一个刻度;
- 向量:sqlite-vec 的 `vec_distance_cosine` **精确**检索,没有近似 / HNSW 索引,几万块以内够用;
- 容量心算:一块 1024 维 float32 向量 4 KB,一万块约 40 MB 加正文与倒排;客户规范 + 几百单工单通常在几十 MB 量级。
  写索引时同目录会临时多出一份副本,磁盘按索引大小的两倍留。

## 1. 前置条件清单

| 项 | 要求 | 说明 |
|---|---|---|
| Python | ≥ 3.9 | 与其他 skill 相同。向量要求这个 Python **能加载 SQLite 扩展**:macOS 系统自带的 `/usr/bin/python3` 不行(其余照常,只是无向量),用 Homebrew 版;自检见下 |
| Python 包 | `psycopg2 2.9.10`、`cryptography ≥ 41`、`PyYAML ≥ 6`、`sqlite-vec 0.1.9` | 就是 `requirements.txt` 那四个;知识库的向量靠 `sqlite-vec`(锁定 0.1.9,有 x86_64 与 aarch64 的 pip 轮子,不分 Python 版本),离线现场与其他包一样带轮子装(见 `01-installation.md` 第 2 节)。xlsx 用 zipfile 读,Neo4j 用 urllib,不另加依赖 |
| OpenCode | 已安装并能跑模型 | 模型即 OpenCode 配置的模型;脚本不调任何 LLM |
| 图库(可选) | Neo4j 5.x 社区版(≥ 5.19,建议 5.26 LTS) | 需要 Query API v2,见第 3 节;不装则路径走 `graph/*.yaml` |
| embedding 端点(可选) | OpenAI 兼容 `/v1/embeddings` | OpenCode provider 上挂的嵌入模型,或 Ollama / vLLM / Xinference,见第 4 节 |
| 磁盘 | `<kb>/` 所在盘可写 | 索引就在 `<kb>/index/`;写时多一份临时副本 |
| 系统转换器(可选) | `textutil`(macOS)/ `antiword`、`pdftotext`(Linux) | 只在导入 `.doc` / `.pdf` 规范时需要;扫描件不做 OCR |
| Docker(可选) | 任意版本 | 只用于本机起 Neo4j 测试容器(第 10 节),生产不需要 |

sqlite-vec 自检(用跑 skill 的那个 `python3`):

```bash
python3 -c "import sqlite3, sqlite_vec; c = sqlite3.connect(':memory:'); c.enable_load_extension(True); sqlite_vec.load(c); print(c.execute('select vec_version()').fetchone()[0])"
# 打印 v0.1.9 = 能做向量;ModuleNotFoundError = 没装;AttributeError …enable_load_extension = 这个 Python 不许加载扩展
```

网络与端口(OpenCode 主机 → 目标;向量索引是本地文件,**没有数据库端口要开**):

| 目标 | 端口 | 协议 | 备注 |
|---|---|---|---|
| Neo4j(可选) | 7474 | HTTP | 只用 HTTP Query API;**Bolt 7687 不需要开** |
| embedding 端点(可选) | 端点自定(Ollama 11434) | HTTP | 索引侧每批超时 30 s,查询侧 1.5 s |

## 2. 安装 skill(gaussdb-kb 随整包安装)

`gaussdb-kb` 和其他 skill 一样由 `install-opencode.sh` 安装,没有单独步骤:

```bash
cd /path/to/opencode_skill
python3 -m pip install -r requirements.txt      # 已装可跳过;含 sqlite-vec==0.1.9
bash install-opencode.sh                        # 全局:~/.config/opencode/skills/
# bash install-opencode.sh --project /path/to/repo   # 项目级:<repo>/.opencode/skills/
```

安装脚本对 `gaussdb-kb/SKILL.md` 多做一件事:把 `{kbDir}` 替换成知识库目录。**知识库目录与 `skills/` 同级**,不在任何 skill 目录里
(install 会 `rm -rf` 每个 skill 目录,放在里面会被下次重装抹掉):

| 安装方式 | 知识库目录 `<kb>` |
|---|---|
| 全局安装 | `~/.config/opencode/kb/` |
| 项目级安装 | `<repo>/.opencode/kb/` |
| 环境变量覆盖 | `export GSDB_KB_DIR=/data/kb`(优先级:`--kb` 参数 > `GSDB_KB_DIR` > 上面的默认) |

索引文件固定在 `<kb>/index/store.sqlite`,跟着 `<kb>` 走,不用也不能另配。

验证 skill 装好了:

```bash
SKILLS=~/.config/opencode/skills
mkdir -p ~/.config/opencode/kb && chmod 700 ~/.config/opencode/kb   # 知识库目录本身要先建
python3 $SKILLS/gaussdb-kb/scripts/kb.py -h
python3 $SKILLS/gaussdb-kb/scripts/kb.py health     # 此时:> 知识库未接入(知识库是空的(还没导入任何规范或工单;…))——空库不刷屏,预期结果
python3 $SKILLS/gaussdb-kb/scripts/kb.py index      # 建出 <kb>/ 骨架、INDEX.md / RULES.md / CASES.md 与 index/store.sqlite
python3 $SKILLS/gaussdb-kb/scripts/kb.py health
# 期望第一行:> 知识库 … · 模式:向量库+图文件 · 条款 0 · 案例 0 · 原始工单 0 · 向量:未启用(kb.yaml 未配 embeddings) · 图:图文件 0 条已确认边(kb.yaml 未配置 store.graph)
```

**不配任何服务就已经能用了**:导入材料后跑 `kb.py index`,各 skill 报告里的「客户知识库参照」小节开始给出条款、案例与路径。
后面第 3–5 节都是可选的:配 embedding 端点是为了向量语义召回,装 Neo4j 是为了图库;配好后 `setup && index`,装了 Neo4j 即「模式:向量库+图库」。

`$GSDB_HOME` 必须已经设置(其他 skill 的连接配置、Neo4j 的凭据都在这里)。未设置时代码默认 `/workspace/.opencode/skills/common`,
那是现场 GRMP 容器的形态,本机/开发机请显式 `export GSDB_HOME=~/.gdaa`(或你自己的目录,0700)。

## 3. 安装 Neo4j 社区版(可选)

Neo4j 只存图(节点标签 = kind,关系类型 = rel,关系带 confidence / source / case_id / valid_from / valid_to),**不存向量**。
本项目通过 **HTTP Query API v2**(`POST /db/<db>/query/v2`)跑 Cypher,用 urllib 实现,零新依赖;不用 Bolt。
不装 Neo4j,路径从 `graph/*.yaml` 里客户确认过的边走,状态行「模式:向量库+图文件」。

**版本**:Neo4j 5.x,**≥ 5.19**(Query API v2 从这个版本起提供,4.x 与更早的 5.x 只有旧的 Transactional API,会 404),建议 5.26 LTS。
验证过的是 Docker 镜像 `neo4j:5-community`。Neo4j 5 需要 **Java 17**(5.26 也支持 21)。社区版只有一个用户库,名字默认 `neo4j`。

**安装**(任选其一):

```bash
# Debian/Ubuntu:官方 apt 源
wget -O - https://debian.neo4j.com/neotechnology.gpg.key | sudo gpg --dearmor -o /etc/apt/keyrings/neotechnology.gpg
echo 'deb [signed-by=/etc/apt/keyrings/neotechnology.gpg] https://debian.neo4j.com stable 5' | sudo tee /etc/apt/sources.list.d/neo4j.list
sudo apt-get update && sudo apt-get install -y neo4j
# RHEL/Rocky:官方 yum 源
sudo rpm --import https://yum.neo4j.com/neotechnology.gpg.key
printf '[neo4j]\nname=Neo4j Yum Repo\nbaseurl=https://yum.neo4j.com/stable/5\nenabled=1\ngpgcheck=1\n' | sudo tee /etc/yum.repos.d/neo4j.repo
sudo yum install -y neo4j
# tarball:解压后 bin/neo4j;Docker(测试):
docker run -d --name kbneo4j -e NEO4J_AUTH='neo4j/<口令>' -p 7474:7474 neo4j:5-community
```

**初始口令与远程访问**(`neo4j.conf` 在 `/etc/neo4j/` 或 `<安装目录>/conf/`):

```bash
sudo neo4j-admin dbms set-initial-password '<口令>'        # 第一次启动前设;Docker 用 NEO4J_AUTH
# neo4j.conf
server.default_listen_address=0.0.0.0     # 默认只听 localhost;OpenCode 不在同机就必须改
server.http.enabled=true                  # HTTP 7474;只想走 HTTPS 就开 server.https.* 并在 kb.yaml 写 https://
sudo systemctl enable --now neo4j
```

图很小(节点、边都是千级),堆内存默认即可;不需要 APOC 之类插件。

**验证**(在 OpenCode 主机上):

```bash
curl -s -u neo4j:'<口令>' http://<Neo4j主机>:7474/                      # 返回 JSON,含 neo4j_version
curl -s -u neo4j:'<口令>' -H 'Content-Type: application/json' \
     -d '{"statement":"RETURN 1 AS n"}' http://<Neo4j主机>:7474/db/neo4j/query/v2   # {"data":{"fields":["n"],"values":[[1]]}}
```

第二条返回 404 就是版本没到 5.19;返回 503 且主机是 macOS,先看第 8 节的代理条目。

`kb.py setup` 会为每种节点 kind 建一条 `id` 唯一约束;`kb.py index` 每次**整体重建**图(先分批 `DETACH DELETE` 再灌),所以图里不要放别的数据。

## 4. embedding 端点(可选)

向量检索需要一个 OpenAI 兼容的 `/v1/embeddings` 端点(以及第 1 节的 sqlite-vec 能加载)。三种配置,写在 `kb.yaml` 的 `embeddings.source`:

| source | 含义 | 什么时候用 |
|---|---|---|
| `opencode` | 复用 OpenCode 当前模型所属 provider 的 `options.baseURL` 与 key,向 `<baseURL>/embeddings` 请求 `embeddings.model` | provider 是 Ollama / vLLM / Xinference 这类**同时挂了嵌入模型**的本地服务 |
| `url` | 显式 `base_url`(可选 `api_key_env` 指向存 key 的环境变量名) | 聊天模型是纯 API(Kimi 等)没有嵌入接口,另起一个嵌入服务 |
| `none` | 不开向量 | 没有嵌入服务;词法 + 图照常 |

最省事的本地方案是 Ollama + bge-m3(中英混合、1024 维,本项目演示用的就是它):

```bash
# macOS: brew install ollama;Linux: curl -fsSL https://ollama.com/install.sh | sh
ollama pull bge-m3
curl -s http://127.0.0.1:11434/v1/embeddings -H 'Content-Type: application/json' \
     -d '{"model":"bge-m3","input":"锁等待"}' | head -c 200        # 有 "embedding":[ 就通了
```

对应 `kb.yaml`:`embeddings: {source: url, base_url: http://127.0.0.1:11434/v1, model: bge-m3, dims: 1024}`。
**维度(`embeddings.dims`)写进索引后就固定**,换模型要同时改 `dims`,并 `kb.py index --rebuild`。
索引侧每批 30 s 超时、失败隔离、按内容哈希缓存(`<kb>/index/embed-cache/`),重跑不重算。

## 5. 接入配置:凭据 + kb.yaml

向量索引是本地文件,**没有口令**。只有装了 Neo4j 才需要 5.1 的凭据;只配 embedding 的话直接看 5.2。

### 5.1 Neo4j 口令进加密凭据

```bash
cd ~/.config/opencode/skills          # 或源码仓根目录:common/ 要在路径上
export GSDB_HOME=~/.gdaa               # 与其他 skill 共用的状态目录(0700)
python3 -m common.credential_cli set kb-graph     # 交互输入,不回显 → $GSDB_HOME/credentials/kb-graph.enc
# 脚本化:printf '%s' "$PW" | python3 -m common.credential_cli set kb-graph --stdin
```

AES-256-GCM,钥匙在 `$GSDB_HOME/key`,AAD 绑定凭据名(密文挪到别的名字下解不开)。**跨机迁移要连 `key` 一起搬。**

### 5.2 `<kb>/kb.yaml`

```bash
mkdir -p ~/.config/opencode/kb && chmod 700 ~/.config/opencode/kb
cat > ~/.config/opencode/kb/kb.yaml <<'YAML'
store:                           # 只有图库;不装 Neo4j 就删掉整个 store 段
  graph: {url: http://10.0.0.9:7474, user: neo4j, credential: kb-graph, database: neo4j}
embeddings:
  source: url                    # opencode | url | none
  base_url: http://127.0.0.1:11434/v1
  model: bge-m3
  dims: 1024
  # api_key_env: EMBED_API_KEY   # source: url 且端点要 key 时,写环境变量名,不写 key 本身
thresholds: {}                   # 分类型相关度阈值,默认即可,不要为了"多命中"调低
YAML
chmod 600 ~/.config/opencode/kb/kb.yaml
```

| 段 | 字段 | 必填 | 说明 |
|---|---|---|---|
| `store.graph` | `url` `user` `credential` | 否(不配则路径走图文件) | `url` 到 7474 为止,不带路径;HTTPS 写 `https://`;`credential` 是 5.1 里的凭据名 |
| | `database` | 否 | 默认 `neo4j` |
| `embeddings` | `source` | 否(默认 none) | 见第 4 节 |
| | `model` `dims` | source ≠ none 时 | 默认 `bge-m3` / 1024 |
| | `base_url` | source = url 时 | 到 `/v1` 为止 |
| | `api_key_env` | 否 | 环境变量名 |
| `thresholds` | 各类阈值 | 否 | 默认即可 |
| `store.pg` | — | **不用了** | 旧版本留下的段会被忽略、不报错;`kb.py index` / `kb.py health` 会提示可以删掉 |

`kb.yaml` 里只允许连接元数据与凭据名;出现 `password` / `apikey` / `token` 键,配置加载直接报错,这是有意的。

## 6. 初始化与验证

```bash
KB=~/.config/opencode/skills/gaussdb-kb/scripts/kb.py
python3 $KB setup            # 只探测并报告;配了 Neo4j 就建约束。索引文件由下一步 index 建
# 索引      : <kb>/index/store.sqlite · SQLite 3.x · sqlite-vec v0.1.9
# 向量      : 有(sqlite-vec · 精确检索 · 维度 1024)      ← sqlite-vec 加载不了时:无(原因)——只做词法 + 图
# Neo4j     : 5.26.x · 约束已建                           ← 没配 / 连不上:未配置/不可用(路径改走 graph/*.yaml 图文件)
# embedding : url · bge-m3 · 1024 维                      ← 没配:none(未启用)
python3 $KB index            # 建 / 更新 <kb>/index/store.sqlite(配了 Neo4j 再写图);此时 <kb>/ 还是空的:文档 0,正常
python3 $KB health           # 状态行:> 知识库 · 模式:向量库+图库 · 条款 0 · 案例 0 · 原始工单 0 · 向量:sqlite-vec(覆盖 …) · 图:Neo4j 0 条已确认边
python3 $KB contract --apply # 把「先查知识库」的契约块注入 9 个做判断的 skill(health/sqltune/lockwait/…)
```

想在没有客户材料的情况下先验一遍全链路,用仓库自带的示例知识库(27 案例 + 12 条款 + 黄金查询集):

```bash
cd /path/to/opencode_skill
python3 skills/gaussdb-kb/testdata/build_sample.py --out ~/.kb-sample   # 生成文件
cp ~/.config/opencode/kb/kb.yaml ~/.kb-sample/kb.yaml                    # 示例库的索引在 ~/.kb-sample/index/,与正式库互不影响
python3 $KB index  --kb ~/.kb-sample
python3 $KB eval   --kb ~/.kb-sample          # 期望 recall@3: 12/12,金丝雀全中
python3 $KB query  --kb ~/.kb-sample --q "偶发 update 慢 autovacuum"   # 能看到带 ID 的条款/案例/路径
```

注意 Neo4j 是共用的:`kb.yaml` 里配了 `store.graph` 时,示例库的 `index` 会把那个图库**整体重建**成示例图。
正式库已经导入过材料的话,先把示例库 `kb.yaml` 里的 `store` 段删掉(路径走图文件),或验完对正式库重跑一次 `kb.py index`。

真正的验收是三态对照(导入前通用解法 / 导入后引用案例与条款 / 复位后又通用),步骤与演示材料在
`skills/gaussdb-kb/testdata/demo/演示手册.md`、`故障演示手册.md`,脚本在 `scripts/kb/`,结果记录在 `scripts/kb-e2e.md`。
之后的日常使用(导入规范、导入工单、选择列表确认)见 `09-客户知识库.md` 第 3 节。

## 7. 降级即发现(哪种情况会看到什么)

| 情况 | 表现 | 处理 |
|---|---|---|
| `<kb>/` 目录不存在 / `kb.yaml` 无效 | 各 skill 报告里的小节只剩 `> 知识库未接入(原因)`;skill 本身照常 | 建目录后 `kb.py index`;修 `kb.yaml` |
| 还没 index / 索引文件打不开 / 索引是旧格式 | 自动退到**文件模式**:状态行「模式:文件(原因)」,条款/案例/路径照常出,只是没有向量召回 | `kb.py index`(打不开或旧格式用 `--rebuild`),`health` 看到「模式:向量库+…」 |
| 索引写不进去(目录只读、盘满) | `index` 退出码 2 并写明原因;`INDEX.md / RULES.md / CASES.md` 照建,检索退到文件模式(之前建过索引的,读方继续读上一份完整的) | 修好写权限 / 空间后重跑 `kb.py index` |
| sqlite-vec 加载不了 | `kb_meta.vector_engine=none`,状态行「向量:未启用(原因)」;词法 + 图照常 | 见第 8 节;装好后 `index --rebuild` |
| 没配 embedding | 只告警,状态行「向量:未启用(kb.yaml 未配 embeddings)」 | 配好后 `index --fill-missing` 补向量 |
| 配了 embedding 但覆盖率不满 100% | `index` 退出码 2,状态行写覆盖百分比 | 端点修好后 `index --fill-missing` |
| Neo4j 没配 / 不可达 | `index` 只写 SQLite 索引并告警;查询时状态行「模式:向量库+图文件 · 图:图文件 N 条已确认边(原因)」,路径从 `graph/*.yaml` 走 | 不想装 Neo4j 就这样用;修好后重跑 `index` 即回到「向量库+图库」 |
| 查询超时(总预算 3 s,embedding 1.5 s) | 本次不用向量,小节里注明 | 端点太慢就换本地嵌入服务 |
| `kb.yaml` 里还留着 `store.pg`(旧版本) | 忽略,不报错;`index` / `health` 打印一行提示可以删 | 删掉那一段(可选) |

退出码约定:`0` 成功;`1` 运行错误(格式、转换、存储、凭据);`2` 有待处理项(覆盖率不足、索引没写进去、validate 有 error、review 有待定项、
别的进程正在写知识库)。**2 不是失败。**

## 8. 排障表

| 现象 | 原因 | 解决 |
|---|---|---|
| 「向量:未启用(没装 sqlite-vec …)」 | 跑 skill 的那个 Python 下没装 `sqlite-vec` | `python3 -m pip install sqlite-vec==0.1.9`(离线带轮子),第 1 节自检打印 `v0.1.9` 后 `kb.py index --rebuild` |
| 「向量:未启用(加载 sqlite-vec 失败 …)」 | 这个 Python 编译时没开 SQLite 扩展加载(如 macOS 系统自带的 `/usr/bin/python3`) | 换能加载扩展的 Python(Homebrew 等)装 `requirements.txt`,自检通过后 `kb.py index --rebuild` |
| `index` 退出 2,`写索引失败:建不出索引临时文件 …` / `索引换不上去 …` | `<kb>/index/` 只读、属主不对或盘满(写时同目录要多放一份副本) | 修好写权限 / 空间后重跑 `kb.py index`;期间检索照常(文件模式,或上一份索引) |
| 状态行「模式:文件(索引是旧格式或不完整 …)」或「打不开索引文件 …」 | 索引是旧版本建的,或文件坏了 | `kb.py index --rebuild`(只重建派生索引,文件不动) |
| `知识库正被 … 写入,请稍后再试`(退出 2) | 另一个 `index` / 导入正在持知识库写锁 | 等它跑完再跑;确认对方已退出,按提示删锁文件 |
| `取不到凭据 'kb-graph'` | 没跑 `credential_cli set`,或 `$GSDB_HOME` 指错目录 | `echo $GSDB_HOME`;重新 `set kb-graph` |
| Neo4j 返回 404 | 版本 < 5.19,没有 `/query/v2` | 升 Neo4j 5.26 |
| Neo4j 返回 401 | 口令错,或首次启动没设初始口令 | `neo4j-admin dbms set-initial-password`,再 `set kb-graph` |
| Neo4j 连 `http://127.0.0.1:7474` 也 503(macOS) | 系统代理把 127.0.0.1 的请求也交给了代理 | 代码里的 HTTP 客户端已绕过系统代理;仍 503 就检查 `curl --noproxy '*'` 能否通 |
| 远端连不上 7474 | Neo4j 默认只听 localhost | `server.default_listen_address=0.0.0.0` + 防火墙放行 |
| `embeddings 第 0 条维度 768,期望 1024` | 嵌入模型与 `dims` 不符 | 改 `dims` 后 `index --rebuild` |
| `index` 退出 2、覆盖率不到 100% | 嵌入端点超时/失败,失败的块向量留空 | 端点恢复后 `index --fill-missing` |
| `kb.yaml` 报 `不得包含 password` | 把口令写进了 yaml | 删掉,走 5.1 的凭据 |

## 9. 备份、重建、升级、卸载

### 9.1 备份

只备 `<kb>/` 整个目录(含 `kb.yaml`;不含口令)。`index/store.sqlite` 与 Neo4j 都是派生索引,不用备——恢复 `<kb>/` 后
`kb.py index --rebuild` 即回来(一起备了也无妨)。配了 Neo4j 的,换机时重新 `set kb-graph`,或把 `$GSDB_HOME/key` + `credentials/` 一起搬。

### 9.2 重建

索引坏了、索引是旧格式、换嵌入模型、改维度,统一 `kb.py index --rebuild`(清掉派生索引重灌,文件不动;embedding 有缓存,算过的不重算)。
Neo4j 图每次 `index` 本来就整体重建。

### 9.3 升级 skill

`git pull && python3 -m pip install -r requirements.txt && bash install-opencode.sh`。`<kb>/` 与 `skills/` 同级,重装不删;
装完重跑 `kb.py contract --apply`(契约块在安装目录副本里,会被覆盖)。

### 9.4 从高斯 / PG 向量库版本升级(2026-10-23 之前装的)

1. `python3 -m pip install -r requirements.txt`(新增 `sqlite-vec==0.1.9`;离线现场带轮子),`bash install-opencode.sh`;
2. 跑一次 `kb.py index`,建出 `<kb>/index/store.sqlite`。**在这之前检索透明地走文件模式,不中断**;
3. 可选:删掉 `kb.yaml` 里的 `store.pg` 段(留着只会多一行提示);`$GSDB_HOME/credentials/kb-pg.enc` 不再使用,可以删;
4. 原来的知识库专用高斯 / PG 实例不再被访问。里面只有派生索引(`kb_docs / kb_chunks / kb_node_vectors / kb_meta`),
   确认没有别的用途后按你们的流程下线。只想清表的话:openGauss 上表在 `kb` 用户的同名 schema 里,用 omm 清要写
   `DROP TABLE kb.kb_docs …`(带 schema 前缀)或直接以 `kb` 用户执行,否则 `IF EXISTS` 会静默跳过、表原样留着。

### 9.5 卸载

删 `~/.config/opencode/skills/gaussdb-kb`;Neo4j `MATCH (n) DETACH DELETE n`;`<kb>/` 目录是客户资产,要不要删由客户定
(只想清掉派生索引就删 `<kb>/index/`)。
