# 客户知识库安装手册:gaussdb-kb + 高斯/PG 向量库 + Neo4j 图库

> 面向部署/运维:从一台只装了 OpenCode 的主机开始,把 `gaussdb-kb` 及其两个后台库装到能跑 `kb.py health` 显示「已接入」。
> 本文把散在 `01-installation.md`(skill 安装)、`skills/gaussdb-kb/references/storage-setup.md`(接入配置)、
> `09-客户知识库.md`(原理与使用)和 `scripts/kb/containers.sh`(测试容器)里的内容收拢成一份,并补上两个库本身的安装。
> 原理、案例格式、检索策略不在这里重复,见 `09-客户知识库.md`。

## 0. 先看一眼:装什么、装在哪、谁连谁

```
 OpenCode 主机                              知识库专用实例(可同机,可分机)
 ┌──────────────────────────────┐          ┌──────────────────────────────┐
 │ ~/.config/opencode/skills/   │  TCP     │ 高斯/PG:openGauss ≥7.0 DataVec │
 │   common/ (含 common/kb/)    │ ───────▶ │         或 PostgreSQL+pgvector  │
 │   gaussdb-kb/  gaussdb-*/    │ 5432     │   表:kb_docs kb_chunks         │
 │ ~/.config/opencode/kb/       │          │       kb_node_vectors kb_meta   │
 │   kb.yaml + rules/ cases/ …  │  HTTP    ├──────────────────────────────┤
 │ $GSDB_HOME/credentials/      │ ───────▶ │ Neo4j 5 社区版(只存图)         │
 │   kb-pg.enc  kb-graph.enc    │ 7474     │   /db/neo4j/query/v2           │
 └──────────────────────────────┘          └──────────────────────────────┘
          │ HTTP(可选)
          ▼
   embedding 端点(OpenCode provider 或 Ollama 等,/v1/embeddings)
```

五条铁律,装之前先认下来:

1. **知识库用专用实例,不放被管业务库。** 现场被管库经 GRMP 白名单、每条 SQL 都是发布 DML;知识库要建表写数据,只能另起一个实例。
2. **`kb.py` 是直连**(pg8000 走 TCP、urllib 走 HTTP),**不经 GRMP**。OpenCode 主机到两个库的网络必须打通。
3. **文件是唯一真相。** `<kb>/` 目录下的 rules / cases / graph 才是知识库;两个库都是 `kb.py index --rebuild` 可重建的派生索引。备份备 `<kb>/`,库坏了重灌。
4. **口令只进加密凭据**(`$GSDB_HOME/credentials/*.enc`),`kb.yaml` 出现 `password / apikey / token` 直接报错。
5. **向量是可选的。** 没有 embedding 端点、或引擎没有 `vector` 类型,知识库照样工作(词法 + 图),状态行会如实写「向量:未启用」。

## 1. 前置条件清单

| 项 | 要求 | 说明 |
|---|---|---|
| Python | ≥ 3.9 | 与其他 skill 相同;macOS 用 `/usr/bin/python3` 或 Homebrew 版本都行 |
| Python 包 | `pg8000 ≥ 1.30`、`cryptography ≥ 41`、`PyYAML ≥ 6` | 就是 `requirements.txt` 那三个,知识库**没有新增 pip 依赖**(xlsx 用 zipfile 读,Neo4j 用 urllib) |
| OpenCode | 已安装并能跑模型 | 模型即 OpenCode 配置的模型;脚本不调任何 LLM |
| 向量库 | openGauss ≥ 7.0.0(DataVec)**或** PostgreSQL ≥ 14 + pgvector | 二选一,见第 3 节 |
| 图库 | Neo4j 5.x 社区版(≥ 5.19,建议 5.26 LTS) | 需要 Query API v2,见第 4 节 |
| embedding 端点(可选) | OpenAI 兼容 `/v1/embeddings` | OpenCode provider 上挂的嵌入模型,或 Ollama / vLLM / Xinference,见第 5 节 |
| 系统转换器(可选) | `textutil`(macOS)/ `antiword`、`pdftotext`(Linux) | 只在导入 `.doc` / `.pdf` 规范时需要;扫描件不做 OCR |
| Docker(可选) | 任意版本 | 只用于本机测试/演示环境(第 11 节),生产不需要 |

网络与端口(OpenCode 主机 → 目标):

| 目标 | 端口 | 协议 | 备注 |
|---|---|---|---|
| 高斯/PG | 5432(或自定) | TCP,PG 协议 | 认证方式见 3.1 / 3.2 的注意事项 |
| Neo4j | 7474 | HTTP | 只用 HTTP Query API;**Bolt 7687 不需要开** |
| embedding 端点 | 端点自定(Ollama 11434) | HTTP | 索引侧每批超时 30 s,查询侧 1.5 s |

## 2. 安装 skill(gaussdb-kb 随整包安装)

`gaussdb-kb` 和其他 skill 一样由 `install-opencode.sh` 安装,没有单独步骤:

```bash
cd /path/to/opencode_skill
python3 -m pip install -r requirements.txt      # 已装可跳过
bash install-opencode.sh                        # 全局:~/.config/opencode/skills/
# bash install-opencode.sh --project /path/to/repo   # 项目级:<repo>/.opencode/skills/
```

安装脚本对 `gaussdb-kb/SKILL.md` 多做一件事:把 `{kbDir}` 替换成知识库目录。**知识库目录与 `skills/` 同级**,不在任何 skill 目录里
(install 会 `rm -rf` 每个 skill 目录,放在里面会被下次重装抹掉):

| 安装方式 | 知识库目录 `<kb>` |
|---|---|
| 全局安装 | `~/.config/opencode/kb/` |
| 项目级安装 | `<repo>/.opencode/kb/` |
| 环境变量覆盖 | `export GSDB_KB_DIR=/data/kb`(优先级:`--kb` 参数 > `GSDB_KB_DIR` > 上面的默认) |

验证 skill 装好了(此时还没配存储,「未接入」是预期结果):

```bash
SKILLS=~/.config/opencode/skills
python3 $SKILLS/gaussdb-kb/scripts/kb.py -h
python3 $SKILLS/gaussdb-kb/scripts/kb.py health
# 期望第一行:知识库未接入(kb.yaml 未配置 store.pg …)
```

`$GSDB_HOME` 必须已经设置(其他 skill 的连接配置也在这里)。未设置时代码默认 `/workspace/.opencode/skills/common`,那是现场 GRMP 容器的形态,
本机/开发机请显式 `export GSDB_HOME=~/.gdaa`(或你自己的目录,0700)。

## 3. 安装向量库(二选一)

两种引擎在本项目里是**同一套 SQL**:`vector(n)` 类型、`<=>` 余弦距离、`USING hnsw (col vector_cosine_ops)`。
`kb.py setup` 启动时探测 `pg_type` 里有没有 `vector`,有就建向量列和 hnsw 索引,没有就只做词法。
连接用户只需要在知识库那个 database 里有建表权限。

### 3.1 方案 A:openGauss ≥ 7.0(DataVec)

适合已经在用高斯的现场:不引入第二种数据库,向量能力是内置的(**不需要 `CREATE EXTENSION`**)。

**版本**:7.0.0-RC1 起自带 `vector` 类型。本项目验证过的是 Docker 镜像 `opengauss/opengauss:7.0.0-RC1`(x86_64 与 arm64 都有);
`opengauss-server:7.0.0-RC2.B015` 镜像在测试机上 `gs_ctl could not start`,先别用。5.x / 6.x **没有** `vector` 类型,装了也只能词法 + 图。

**安装**:按 openGauss 官方文档做极简安装(`install.sh`)或企业版安装(`gs_preinstall` / `gs_install`),本文不重复;
测试可以直接用 Docker(见第 11 节)。装好后以 `omm` 登录 `gsql -d postgres -p 5432 -r`。

**初始化(以 omm 执行)**——顺序很重要,认证方式要在建用户**之前**定:

```sql
-- 1) 认证方式:pg8000 只认 md5 / SCRAM,不认 openGauss 私有的 sha256 握手。
--    password_encryption_type 必须先改成 0(md5),再建用户,口令才会以 md5 存。
--    (官方 Docker 镜像默认就是这么配的;自装实例默认是 2,漏了这一步 pg8000 会报认证失败)
ALTER SYSTEM SET password_encryption_type = 0;     -- 或 gs_guc reload -D $PGDATA -c "password_encryption_type=0"

-- 2) 专用用户与库。openGauss 的初始用户(omm/gaussdb)禁止远程登录,必须建普通用户。
--    口令复杂度默认要求 ≥ 8 位且含大写/小写/数字/特殊字符中的三类。
CREATE USER kb WITH PASSWORD 'Kb_Strong_Pass_1@';
CREATE DATABASE kb OWNER kb;

-- 3) 确认向量类型在
SELECT 1 FROM pg_type WHERE typname = 'vector';     -- 返回 1 行才对
```

**远程访问**(在数据库主机上,`$PGDATA` 是数据目录):

```bash
gs_guc set -D $PGDATA -c "listen_addresses='*'"
gs_guc set -D $PGDATA -h "host kb kb <OpenCode主机IP>/32 md5"     # 只放行知识库用户到知识库
gs_ctl restart -D $PGDATA
```

**验证**(在 OpenCode 主机上):

```bash
python3 - <<'PY'
import pg8000.native
c = pg8000.native.Connection(user="kb", password="Kb_Strong_Pass_1@", host="<数据库IP>", port=5432, database="kb")
print(c.run("SELECT version()")[0][0][:60]); print("vector:", c.run("SELECT 1 FROM pg_type WHERE typname='vector'"))
c.close()
PY
```

### 3.2 方案 B:PostgreSQL + pgvector

适合没有高斯 7 的现场,或者想把知识库放在一台通用 PG 上。

**安装 PG 与 pgvector**(任选其一):

```bash
# Debian/Ubuntu(PGDG 源)
sudo apt-get install -y postgresql-16 postgresql-16-pgvector
# RHEL/Rocky(PGDG 源)
sudo dnf install -y postgresql16-server pgvector_16
# 源码编译(任意平台,需 pg_config)
git clone --branch v0.7.4 https://github.com/pgvector/pgvector.git && cd pgvector && make && sudo make install
# Docker(测试)
docker run -d --name kbpg -e POSTGRES_USER=kb -e POSTGRES_DB=kb -e POSTGRES_PASSWORD='<口令>' -p 5432:5432 pgvector/pgvector:pg16
```

**初始化(超级用户执行)**:

```sql
CREATE ROLE kb LOGIN PASSWORD '<口令>';
CREATE DATABASE kb OWNER kb;
\c kb
CREATE EXTENSION IF NOT EXISTS vector;     -- 装扩展需要超级用户;不预装的话 setup 会自己试一次,权限不够就退化为无向量并在状态行写明
```

**远程访问**:`postgresql.conf` 里 `listen_addresses = '*'`;`pg_hba.conf` 加一行 `host kb kb <OpenCode主机IP>/32 scram-sha-256`;`pg_ctl reload`。

### 3.3 两种引擎共同的事

`kb.py setup` 会在知识库 database 里幂等建这些对象(用户只需在该库里有 CREATE 权限):

| 对象 | 用途 |
|---|---|
| `kb_docs` | 文档头:条款文件 / 指南 / 案例 / 原始工单,带 content_hash 做增量 |
| `kb_chunks` | 切块正文 + `lex tsvector`(gin 索引)+ `embedding vector(n)`(有向量时) |
| `kb_node_vectors` | 图节点(现象/根因/处置…)的词法与向量,`signals` 列存复发标志 |
| `kb_meta` | engine / vector_engine(datavec / pgvector / none)/ hnsw / dims / schema_version |
| `*_emb_idx` | hnsw 索引(`m=16, ef_construction=64`);建不成只告警,退化为顺序扫描 |

容量心算:一块 1024 维 float 向量约 4 KB,一万块正文约 40 MB 加索引;客户规范 + 几百单工单通常在几十 MB 量级。
**维度(`embeddings.dims`)一旦建表就固定**,换嵌入模型改了维度必须 `kb.py index --rebuild`。

## 4. 安装 Neo4j 社区版

Neo4j 只存图(节点标签 = kind,关系类型 = rel,关系带 confidence / source / case_id / valid_from / valid_to),**不存向量**。
本项目通过 **HTTP Query API v2**(`POST /db/<db>/query/v2`)跑 Cypher,用 urllib 实现,零新依赖;不用 Bolt。

**版本**:Neo4j 5.x,**≥ 5.19**(Query API v2 从这个版本起提供,4.x 与更早的 5.x 只有旧的 Transactional API,会 404),建议 5.26 LTS。
验证过的是 Docker 镜像 `neo4j:5-community`。Neo4j 5 需要 **Java 17**(5.26 也支持 21)。社区版只有一个用户库,名字默认 `neo4j`。

**安装**(任选其一):

```bash
# Debian/Ubuntu:官方 apt 源
wget -O - https://debian.neo4j.com/neotechnology.gpg.key | sudo gpg --dearmor -o /etc/apt/keyrings/neotechnology.gpg
echo 'deb [signed-by=/etc/apt/keyrings/neotechnology.gpg] https://debian.neo4j.com stable 5' | sudo tee /etc/apt/sources.list.d/neo4j.list
sudo apt-get update && sudo apt-get install -y neo4j
# RHEL/Rocky:官方 yum 源
sudo rpm --import https://yum.neo4j.com/neotechnology.gpg.key
printf '[neo4j]\nname=Neo4j Yum Repo\nbaseurl=https://yum.neo4j.com/stable/5\nenabled=1\ngpgcheck=1\n' | sudo tee /etc/yum.repos.d/neo4j.repo
sudo yum install -y neo4j
# tarball:解压后 bin/neo4j;Docker(测试):
docker run -d --name kbneo4j -e NEO4J_AUTH='neo4j/<口令>' -p 7474:7474 neo4j:5-community
```

**初始口令与远程访问**(`neo4j.conf` 在 `/etc/neo4j/` 或 `<安装目录>/conf/`):

```bash
sudo neo4j-admin dbms set-initial-password '<口令>'        # 第一次启动前设;Docker 用 NEO4J_AUTH
# neo4j.conf
server.default_listen_address=0.0.0.0     # 默认只听 localhost;OpenCode 不在同机就必须改
server.http.enabled=true                  # HTTP 7474;只想走 HTTPS 就开 server.https.* 并在 kb.yaml 写 https://
sudo systemctl enable --now neo4j
```

图很小(节点、边都是千级),堆内存默认即可;不需要 APOC 之类插件。

**验证**(在 OpenCode 主机上):

```bash
curl -s -u neo4j:'<口令>' http://<Neo4j主机>:7474/                      # 返回 JSON,含 neo4j_version
curl -s -u neo4j:'<口令>' -H 'Content-Type: application/json' \
     -d '{"statement":"RETURN 1 AS n"}' http://<Neo4j主机>:7474/db/neo4j/query/v2   # {"data":{"fields":["n"],"values":[[1]]}}
```

第二条返回 404 就是版本没到 5.19;返回 503 且主机是 macOS,先看第 9 节的代理条目。

`kb.py setup` 会为每种节点 kind 建一条 `id` 唯一约束;`kb.py index` 每次**整体重建**图(先分批 `DETACH DELETE` 再灌),所以图里不要放别的数据。

## 5. embedding 端点(可选)

向量检索需要一个 OpenAI 兼容的 `/v1/embeddings` 端点。三种配置,写在 `kb.yaml` 的 `embeddings.source`:

| source | 含义 | 什么时候用 |
|---|---|---|
| `opencode` | 复用 OpenCode 当前模型所属 provider 的 `options.baseURL` 与 key,向 `<baseURL>/embeddings` 请求 `embeddings.model` | provider 是 Ollama / vLLM / Xinference 这类**同时挂了嵌入模型**的本地服务 |
| `url` | 显式 `base_url`(可选 `api_key_env` 指向存 key 的环境变量名) | 聊天模型是纯 API(Kimi 等)没有嵌入接口,另起一个嵌入服务 |
| `none` | 不开向量 | 没有嵌入服务;词法 + 图照常 |

最省事的本地方案是 Ollama + bge-m3(中英混合、1024 维,本项目演示用的就是它):

```bash
# macOS: brew install ollama;Linux: curl -fsSL https://ollama.com/install.sh | sh
ollama pull bge-m3
curl -s http://127.0.0.1:11434/v1/embeddings -H 'Content-Type: application/json' \
     -d '{"model":"bge-m3","input":"锁等待"}' | head -c 200        # 有 "embedding":[ 就通了
```

对应 `kb.yaml`:`embeddings: {source: url, base_url: http://127.0.0.1:11434/v1, model: bge-m3, dims: 1024}`。
换模型要同时改 `dims`,并 `kb.py index --rebuild`。索引侧每批 30 s 超时、失败隔离、按内容哈希缓存(`<kb>/index/embed-cache/`),重跑不重算。

## 6. 接入配置:凭据 + kb.yaml

### 6.1 口令进加密凭据

```bash
cd ~/.config/opencode/skills          # 或源码仓根目录:common/ 要在路径上
export GSDB_HOME=~/.gdaa               # 与其他 skill 共用的状态目录(0700)
python3 -m common.credential_cli set kb-pg        # 交互输入,不回显 → $GSDB_HOME/credentials/kb-pg.enc
python3 -m common.credential_cli set kb-graph     # Neo4j 口令
# 脚本化:printf '%s' "$PW" | python3 -m common.credential_cli set kb-pg --stdin
```

AES-256-GCM,钥匙在 `$GSDB_HOME/key`,AAD 绑定凭据名(密文挪到别的名字下解不开)。**跨机迁移要连 `key` 一起搬。**

### 6.2 `<kb>/kb.yaml`

```bash
mkdir -p ~/.config/opencode/kb && chmod 700 ~/.config/opencode/kb
cat > ~/.config/opencode/kb/kb.yaml <<'YAML'
store:
  pg:    {host: 10.0.0.9, port: 5432, database: kb, user: kb, credential: kb-pg, sslmode: disable}
  graph: {url: http://10.0.0.9:7474, user: neo4j, credential: kb-graph, database: neo4j}
embeddings:
  source: url                    # opencode | url | none
  base_url: http://127.0.0.1:11434/v1
  model: bge-m3
  dims: 1024
  # api_key_env: EMBED_API_KEY   # source: url 且端点要 key 时,写环境变量名,不写 key 本身
thresholds: {}                   # 分类型相关度阈值,默认即可,不要为了"多命中"调低
YAML
chmod 600 ~/.config/opencode/kb/kb.yaml
```

| 段 | 字段 | 必填 | 说明 |
|---|---|---|---|
| `store.pg` | `host` `port` `database` `user` `credential` | 是(port 默认 5432) | `credential` 是 6.1 里的凭据名 |
| | `sslmode` | 否 | `disable / allow / prefer / require / verify-ca / verify-full`,同 `config.yaml` |
| `store.graph` | `url` `user` `credential` | 否(不配则图能力关闭) | `url` 到 7474 为止,不带路径;HTTPS 写 `https://` |
| | `database` | 否 | 默认 `neo4j` |
| `embeddings` | `source` | 否(默认 none) | 见第 5 节 |
| | `model` `dims` | source ≠ none 时 | 默认 `bge-m3` / 1024 |
| | `base_url` | source = url 时 | 到 `/v1` 为止 |
| | `api_key_env` | 否 | 环境变量名 |
| `thresholds` | 各类阈值 | 否 | 默认即可 |

`kb.yaml` 里只允许连接元数据与凭据名;出现 `password` / `apikey` / `token` 键,配置加载直接报错,这是有意的。

## 7. 初始化与验证

```bash
KB=~/.config/opencode/skills/gaussdb-kb/scripts/kb.py
python3 $KB setup
# 高斯/PG   : opengauss · (openGauss 7.0.0 …)      ← 或 postgresql · PostgreSQL 16.x
# 向量      : 有(datavec) · hnsw · 维度 1024        ← 或 有(pgvector);无 vector 类型时:无——只做词法 + 图
# Neo4j     : 5.26.x · 约束已建
# embedding : url · bge-m3 · 1024 维
python3 $KB index            # 此时 <kb>/ 还是空的:文档 0,正常
python3 $KB health           # 状态行:> 知识库 · 条款 0 · 案例 0 · 原始工单 0 · 向量:bge-m3(…) · 图:ok  ← 不再是「知识库未接入」
python3 $KB contract --apply # 把「先查知识库」的契约块注入 9 个做判断的 skill(health/sqltune/lockwait/…)
```

想在没有客户材料的情况下先验一遍全链路,用仓库自带的示例知识库(27 案例 + 12 条款 + 黄金查询集):

```bash
cd /path/to/opencode_skill
python3 skills/gaussdb-kb/testdata/build_sample.py --out ~/.kb-sample   # 生成文件
cp ~/.config/opencode/kb/kb.yaml ~/.kb-sample/kb.yaml
python3 $KB index  --kb ~/.kb-sample
python3 $KB eval   --kb ~/.kb-sample          # 期望 recall@3: 12/12,金丝雀全中
python3 $KB query  --kb ~/.kb-sample --q "偶发 update 慢 autovacuum"   # 能看到带 ID 的条款/案例/路径
```

真正的验收是三态对照(导入前通用解法 / 导入后引用案例与条款 / 复位后又通用),步骤与演示材料在
`skills/gaussdb-kb/testdata/demo/演示手册.md`、`故障演示手册.md`,脚本在 `scripts/kb/`,结果记录在 `scripts/kb-e2e.md`。
之后的日常使用(导入规范、导入工单、选择列表确认)见 `09-客户知识库.md` 第 3 节。

## 8. 降级即发现(哪种情况会看到什么)

| 情况 | 表现 | 处理 |
|---|---|---|
| `kb.yaml` 没配 `store.pg` / 高斯·PG 连不上 / 还没 index | 各 skill 报告里的小节只剩 `> 知识库未接入(原因)`;skill 本身照常 | 按原因修,`kb.py health` 复核 |
| 引擎没有 `vector` 类型 | `kb_meta.vector_engine=none`,状态行「向量:未启用(存储引擎无 vector 类型)」 | 高斯升到 7.0,或 PG 装 pgvector 后 `setup` + `index --rebuild` |
| 没配 embedding | 只告警,状态行「向量:未启用(kb.yaml 未配 embeddings)」 | 配好后 `index --fill-missing` 补向量 |
| 配了 embedding 但覆盖率不满 100% | `index` 退出码 2,状态行写覆盖百分比 | 端点修好后 `index --fill-missing` |
| hnsw 索引建不成 | setup 告警,向量检索顺序扫描 | 数据量小无所谓;大了升引擎版本 |
| Neo4j 不可达 | `index` 只写高斯/PG 并告警;查询时状态行「图:不可用」,路径小节为空 | 修好后重跑 `index` |
| 查询超时(总预算 3 s,embedding 1.5 s) | 本次不用向量,小节里注明 | 端点太慢就换本地嵌入服务 |

退出码约定:`0` 成功;`1` 运行错误(格式、转换、存储、凭据);`2` 有待处理项(覆盖率不足、validate 有 error、review 有待定项)。**2 不是失败。**

## 9. 排障表

| 现象 | 原因 | 解决 |
|---|---|---|
| `取不到凭据 'kb-pg'` | 没跑 `credential_cli set`,或 `$GSDB_HOME` 指错目录 | `echo $GSDB_HOME`;重新 `set kb-pg` |
| pg8000 连 openGauss 报认证失败,口令确定没错 | 用户是在 `password_encryption_type=2`(sha256)下建的,pg8000 不认 openGauss 私有握手 | 改成 0 后 `ALTER USER kb IDENTIFIED BY '<口令>'` 重设口令,pg_hba 用 `md5` |
| openGauss 报初始用户不能远程登录 | 用 omm / gaussdb 连的 | 用 3.1 建的 `kb` 用户 |
| `存储引擎没有 vector 类型` | openGauss < 7.0;或 PG 没装 pgvector / 没 `CREATE EXTENSION` | 见 3.1 / 3.2 |
| setup 报 `CREATE EXTENSION` 权限不够 | pgvector 扩展要超级用户 | DBA 预先在 kb 库执行 `CREATE EXTENSION vector` |
| Neo4j 返回 404 | 版本 < 5.19,没有 `/query/v2` | 升 Neo4j 5.26 |
| Neo4j 返回 401 | 口令错,或首次启动没设初始口令 | `neo4j-admin dbms set-initial-password`,再 `set kb-graph` |
| Neo4j 连 `http://127.0.0.1:7474` 也 503(macOS) | 系统代理把 127.0.0.1 的请求也交给了代理 | 代码里的 HTTP 客户端已绕过系统代理;仍 503 就检查 `curl --noproxy '*'` 能否通 |
| 远端连不上 7474 | Neo4j 默认只听 localhost | `server.default_listen_address=0.0.0.0` + 防火墙放行 |
| `embeddings 第 0 条维度 768,期望 1024` | 嵌入模型与 `dims` 不符 | 改 `dims` 后 `index --rebuild` |
| `index` 退出 2、覆盖率不到 100% | 嵌入端点超时/失败,失败的块向量留空 | 端点恢复后 `index --fill-missing` |
| 本机测试库「连不上」但容器在跑 | OrbStack 等虚拟机抢占了 5433–5436 | `lsof -iTCP:<port>` 先查端口再查口令 |
| `kb.yaml` 报 `不得包含 password` | 把口令写进了 yaml | 删掉,走 6.1 的凭据 |

## 10. 备份、重建、升级、卸载

- **备份**:备 `<kb>/` 整个目录(含 `kb.yaml`;不含口令)和 `$GSDB_HOME/key` + `credentials/`。两个库不用备。
- **重建**:库坏了、换实例、换嵌入模型、改维度,统一 `kb.py setup && kb.py index --rebuild`(清两库重灌,文件不动)。
- **升级 skill**:`git pull && bash install-opencode.sh`。`<kb>/` 与 `skills/` 同级,重装不删;装完重跑 `kb.py contract --apply`(契约块在安装目录副本里,会被覆盖)。
- **卸载**:删 `~/.config/opencode/skills/gaussdb-kb`;库侧 `DROP TABLE kb_chunks, kb_node_vectors, kb_docs, kb_meta;`,Neo4j `MATCH (n) DETACH DELETE n`;
  `<kb>/` 目录是客户资产,要不要删由客户定。

## 11. 本机测试 / 演示环境(开发机,非生产)

`scripts/kb/containers.sh` 幂等起三个容器,口令首次运行自动生成到 `~/.kb-test.env`(0600),不打印:

| 容器 | 镜像 | 端口 | 库 / 用户 |
|---|---|---|---|
| `kbpg` | `pgvector/pgvector:pg16` | 5440 → 5432 | `kb` / `kb` |
| `kbneo4j` | `neo4j:5-community` | 7474, 7687 | `neo4j` / `neo4j` |
| `og7`(可选,`KB_WITH_OG7=1`) | `opengauss/opengauss:7.0.0-RC1` | 5439 → 5432 | `postgres` / `gaussdb` |

```bash
bash scripts/kb/containers.sh                 # 起容器;末尾打印 live 测试要 export 的三个变量
python3 -m common.credential_cli set kb-pg    # 输入 ~/.kb-test.env 里的 KB_PG_PW

bash install-opencode.sh
bash scripts/kb/demo-reset.sh                 # <kb> 复位到「未接入」并写好指向容器的 kb.yaml;本机有 Ollama bge-m3 会自动开向量
python3 -m pytest tests -q -m "not live"      # 单测;真库:source ~/.kb-test.env 后按 containers.sh 末尾的提示 export,再 -m live
```

演示脚本:`scripts/kb/threestate.sh`(检索层三态)、`model-demo.sh`(模型层八步,`opencode run`)、`fault-lockwait.sh start|status|stop`(锁等待故障)。
