# 客户知识库(gaussdb-kb):规范 + 工单 → 向量库 + 图库,让各 skill 优先按客户经验作答

> 取代原 `gaussdb-kbimport`(1.x 的规范条款化路径全部保留)。设计稿:`docs/superpowers/specs/2026-09-02-knowledge-base-skill-design.md`。

## 1. 它解决什么

没有知识库时,模型对「未使用索引」「缓存命中率低」这类发现只能给通用解法。导入客户的规范与工单之后,
每个诊断 skill(health 及其子 skill、sqltune、sqlreview、proctune、wdr、memanalyze)的脚本会**按每条发现**查库,
把结果作为固定小节 `## 客户知识库参照` 写进报告——「贵行规范怎么说 / 本行历史上怎么处置 / 现象→根因→处置 的确认链」,
每条带 ID 与出处;模型在**已经看到客户先例**的前提下作答,契约要求它以此为处置建议的首选依据、引用必带 ID、查不到就如实说通用。

三态验收(`scripts/kb-e2e.md`):导入前小节写「未接入」;导入后每条发现挂对条款/案例;移走知识库又回到「未接入」。

## 2. 组成

| 部分 | 位置 | 说明 |
|---|---|---|
| skill | `skills/gaussdb-kb/` | `kb.py` 子命令:ingest / propose / review / apply / validate / index / query / setup / health / feedback / eval / contract |
| 共享检索层 | `common/kb/` | config / text / store_pg / store_graph / embed / cases / graphfiles / indexer / ingest / query / render |
| 知识库目录 | `<安装根>/kb/`(与 `skills/` 同级,重装不删) | 文件 = 唯一真相:`rules/ guides/ errata/ archive/`(条款)、`cases/`(案例)、`graph/`(三元组 + 别名)、`sources/`(原文快照)、`inbox/`(待处理)、`eval/`、`kb.yaml` |
| 向量 + 词法 | 高斯/PG:**openGauss ≥ 7.0(DataVec)** 或 PostgreSQL + pgvector | 同一套 SQL;启动探测 `vector` 类型,没有就只做词法,状态行如实写 |
| 图 | **Neo4j**(社区版) | HTTP Query API,零新依赖;只存强类型边(EXHIBITS / CAUSED_BY / HANDLED_BY / INVOLVES / CONSTRAINS / REFERENCES / DEPENDS_ON),无共现边 |
| embedding | OpenCode 配置的 provider 端点(或显式 url) | 可选;没有就词法 + 图 |

两个库都是 `kb.py index --rebuild` 可重建的派生索引。现场被管库经 GRMP 白名单,**知识库必须用单独的实例**。
两个库怎么装、用户与认证、`kb.yaml` 与凭据、验证与排障,见 [10-知识库安装手册](10-知识库安装手册.md)
(skill 自带的 `skills/gaussdb-kb/references/storage-setup.md` 是它的接入配置节选;口令走 `python3 -m common.credential_cli set kb-pg / kb-graph`)。

## 3. 使用流程

```bash
python3 skills/gaussdb-kb/scripts/kb.py setup                    # 建表建约束,报告引擎能力
python3 skills/gaussdb-kb/scripts/kb.py ingest 运维规范.docx      # 规范 → inbox,模型条款化 → rules/guides/errata
python3 skills/gaussdb-kb/scripts/kb.py ingest 工单导出.xlsx --redact   # 工单 → 一单一文件(原文当天可检索)
python3 skills/gaussdb-kb/scripts/kb.py propose q1               # 首次只问 8 个转化策略问题、不出工作单(答案写 strategies/tickets.yaml,或 --use-defaults);再跑出工作单,模型填 candidates.json(每项附原文摘录)
python3 skills/gaussdb-kb/scripts/kb.py review q1                # 校验 + 编号选择列表(写库前唯一闸门)
python3 skills/gaussdb-kb/scripts/kb.py apply q1 --all-but-edges --accept 7,8 --user 12345
python3 skills/gaussdb-kb/scripts/kb.py validate && python3 skills/gaussdb-kb/scripts/kb.py index
python3 skills/gaussdb-kb/scripts/kb.py query --q "偶发 update 慢 autovacuum"      # 纯问答同款小节
python3 skills/gaussdb-kb/scripts/kb.py health                   # 状态行、覆盖率、待处理、缺口清单
python3 skills/gaussdb-kb/scripts/kb.py eval                     # 黄金查询集 + 金丝雀
python3 skills/gaussdb-kb/scripts/kb.py cite-check --file 回答.md  # 核对回答里引用的案例/条款 ID:未找到 = 疑似编造(退出 2),已废止标 ⚠
python3 skills/gaussdb-kb/scripts/kb.py contract --apply         # 契约块注入 9 个做判断的 skill
```

模型在会话里做的只有:条款分类、按工作单抽案例候选、把选择列表原样呈现给用户并收集回答。
**写库之前一律经选择列表**:字段/实体按建议默认接受,**边没有默认**——用户接受的边 confidence=1.0 才进「本行历史路径」。

## 4. 案例与图的格式

案例 `cases/S<级>-YYYYMMDD-<系统>-<标题>.md`:frontmatter(系统 / 发生时间 / 级别 / 主要因素 / 结论强度 / 出处 / 对象 / 复发标志 …)+
四节「现场 / 判断 / 处置 / 复发标志」。结论强度(已确认 1.0 / 推测 0.6 / 待验证 0.3)是该案例所有边的置信度;
复发标志是按发现匹配案例的信号。三元组 `graph/*.yaml`:`src —rel→ dst`,带 confidence / status / source / case / valid_from。
详见 `skills/gaussdb-kb/references/{case-format,graph-schema,selection-list}.md`。

## 5. 检索怎么做、怎么不凑数

按发现:code + 指标 + 证据 → 词法(中文二元组 + 标识符,tsvector 字面量,两种引擎行为一致)∥ 向量(有 embedding 时)∥
图扩展(向量/词法先命中**现象节点**,再沿已确认边走出 现象→根因→处置)→ RRF 融合 → 分类型 top-k。
两道门防凑数:绝对门槛(命中 ≥1 个强 token——标识符/代码/≥6 字符词,且 ≥2 个 token)、幸存者内相对最高分的比例;
低于门槛整类返回「无」,由渲染层明写「无对应条款 / 无相似案例 / 路径:无」。查不到的发现记进 `index/misses.log`,`health` 汇总成缺口清单。

## 6. 降级即发现

| 情况 | 表现 |
|---|---|
| `<kb>/` 不存在 / `kb.yaml` 没配存储 / 连不上 / 没索引 | 小节只剩 `> 知识库未接入(原因)`;skill 照常 |
| 引擎无 vector 类型 / 没配 embedding | 状态行「向量:未启用(原因)」;词法 + 图照常 |
| 配了 embedding 但覆盖不满 | `index` 退出码 2,`--fill-missing` 补;状态行写覆盖百分比 |
| Neo4j 不可达 | 状态行「图:不可用」,路径为空;index 只写高斯/PG 并告警 |
| 查询超时(3 s 预算,embedding 1.5 s) | 本次不用向量,小节里注明 |

## 7. 示例知识库与测试

`skills/gaussdb-kb/testdata/build_sample.py` 生成 27 份虚构案例(5 个"客户做法与通用相反"的金丝雀、3 个干扰)、12 条款、黄金查询集。
测试:`tests/test_kb_*.py`(单测)+ `-m live`(pgvector / og7 DataVec / Neo4j 容器)。Mac 上:`~/kb-containers.sh` 起容器,
`~/kb-threestate.sh` 跑三态。**单测绿不算完,三态要真跑。**

## 8. 安全

- `kb.yaml` 只写连接元数据与凭据名,出现 `password/apikey/token` 直接报错;口令在 `$GSDB_HOME/credentials/*.enc`;
- 工单原文 `--redact` 脱敏 IP / 手机号 / 证件号 / 邮箱;`<kb>/` 0700;
- 本 skill 不连被管业务库;HTTP 客户端绕过系统代理(macOS 会把 127.0.0.1 也交给代理)。
